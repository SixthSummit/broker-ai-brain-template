# Data

What happened: the brain's diary. Summaries and logs only. Raw transcripts, recordings and copies of
client records stay in the tool they came from.

## Folders

| Folder | What it holds | Written by |
|---|---|---|
| `session-logs/<bot>/YYYY-MM-DD.md` | Each bot's daily log of real work | Every bot, in its own folder ([[brain/session-logs]]) |
| `meetings/YYYY-MM-DD-<who>-<topic>.md` | Meeting summaries | Any bot, with [[skills/meeting-summary]] |
| `calls/YYYY-MM-DD-<who>-<topic>.md` | Call summaries | Any bot, with [[skills/call-summary]] |

A new kind of record gets its own subfolder and a row here, such as `data/open-houses/` for a
broker who wants notes from every open house ([[brain/adding-to-the-brain]]).

## What a summary may hold

Keep what helps the next conversation: names, the date and time, who was there, what it was about,
what the people want, their plans, timeline and concerns, the decisions, the next steps and
everyone's preferences.

Leave out only a client's personal details (hard rule 1 in `AGENTS.md`) and any password, login,
key or token (hard rule 2). Where a summary needs one of those client details, write where it lives
instead: "income details in the client list".

## Reading and writing

- **Read only the files a task needs.** To find something, list the folder and pick by the date and
  the name, rather than opening every file.
- **Before you write a summary,** check whether one for the same date already exists. The same
  meeting or call (the same start time): add to it rather than write a second. A different one
  with the same name on the same day gets `-2` at the end of its file name (`-3` for a third).
